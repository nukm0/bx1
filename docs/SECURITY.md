# Безопасность и приватность

- Telegram `initData` должен проверяться сервером по официальному алгоритму HMAC; клиентские `initDataUnsafe` и присланный `userId` не являются доказательством личности.
- После проверки `initData` проверяйте `auth_date` и отклоняйте слишком старые данные.
- Телефон запрашивается нативной кнопкой Telegram `request_contact`; сервер принимает его только если contact user ID совпадает с авторизованным пользователем и номер нормализован в формат `+7`. Обычный текст не считается подтверждением.
- Публичный профиль не содержит телефон. Телефон доступен только владельцу и админам с разрешением, через отдельный защищённый endpoint.
- Числовой ID владельца хранится в секрете окружения. Username может измениться, поэтому не используйте `@nukm0` как единственную проверку прав.
- Все административные действия требуют RBAC на сервере, проверки владельца ресурса и записи в `AuditLog`.
- Доказательства модерации храните приватно и выдавайте по короткоживущим ссылкам только уполномоченным ролям.
- В production включите HTTPS, безопасные заголовки, rate limiting, CSRF-защиту при cookie-сессиях, резервные копии, мониторинг, проверку файлов и обновление зависимостей.
- Не отправляйте номер телефона, токен бота, initData или доказательства в логи и аналитику.
